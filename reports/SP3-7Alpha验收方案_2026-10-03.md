## 一、目标与范围

- **目标**：以真实用户（10 人）在真实服务端 + 真实厂商 API Key 上完成四阶段任务全链路试用，
  收集功能完成率、冷启动/崩溃率基线与缺陷清单，为 Beta（SP5-1）与 MVP 锁定（SP1-7/SP2-8）提供证据。
- **范围**：注册登录 → Key 配置 → 内容库/模板 → 四阶段任务（含门禁驳回/重试/人工干预）→
  积分/账单 → 离线宽限（断网演练）→ 合规声明导出 → 任务历史续跑。
- **形态说明**：Electron 壳与 preload 桥随 SP5-3 打包接入；本窗口 Alpha 以 renderer 生产构建
  （vite build 产物，253KB/gzip 79KB）+ 服务端 dev/staging 环境执行，壳接入后按本方案补一轮壳回归。

## 四、收集指标与判定标准

- **功能完成率**：每场景 ≥9/10 人通过即该场景通过；10 场景 ≥9 通过 → 功能验收 Go。
- **冷启动基线**：BootTimer.appReadyMs 实测值（Settings 页可见+上报遥测），目标任务 <3s（PRD 6.1）。
  达标率：10 台设备 90% 达标。冷启动/崩溃率按 SP3-7 埋点（BootTimer/CrashGuard）自动汇总。
- **崩溃率**：CrashGuard stats（试用全程）<1% 会话崩溃；P0 缺陷（数据丢失/资金错误/Key 泄露）0 容忍。
- **主观项**：每场景 1-5 分满意度和自由文本；总分均值 ≥3.5。
- **缺陷闭环**：发现即入表；P0/P1 当日修复回归（资金域改动强制 ARCH 双审复核），P2 排期。

> **勘误（2026-10-06 附）**：上文"崩溃率 <1% 会话崩溃"为笔误，统一以 PRD 技术目标 **<0.5%** 为准（QA 手册、重规划 §5.3、主计划 Phase 2、执行手册 W18 同口径）；本文件其余内容不变。另：本方案判定时引用的真题回归集规模以《客户端与引擎开发计划》§3.2 ≥20 题为准。详见 reports/方案与文档一致性核查_2026-10-06.md。
