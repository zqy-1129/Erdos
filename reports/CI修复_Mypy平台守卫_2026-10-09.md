# CI 修复：engine-ci Mypy 平台守卫（Linux attr-defined 消除）（2026-10-09）

> 背景：engine-ci「lint + type + test」任务对 push develop **无路径过滤**（任何推送均触发）；其 Mypy 步骤在 ubuntu 侧稳定失败
> 影响面：仅测试文件最小改动；零接口 / 契约 / 行为变更

## 1. 根因

`engine/tests/test_entry_wiring.py` 使用 Windows 专属常量：

- `subprocess.CREATE_NEW_PROCESS_GROUP`（_spawn 的 creationflags）
- `signal.CTRL_BREAK_EVENT`（SIGTERM 用例的 Windows 分支）

原保护为 **运行期** `os.name == "nt"`——但 mypy 的静态平台收窄**只识别 `sys.platform`**（typeshed 以
`if sys.platform == "win32"` 定义这些名字）；Linux（ubuntu CI）侧属性不存在 → 2 处 `attr-defined`，
Mypy 步骤 exit 1（截图与本机复现逐字一致：`Found 2 errors in 1 file (checked 68 source files)`）。

## 2. 修复

两处守卫改为 `if sys.platform == "win32":`（运行语义等价：CPython 下 `os.name == "nt"` ⟺ `sys.platform == "win32"`）。

未使用 `# type: ignore`：mypy 配置 `warn_unused_ignores = true`，忽略注释会在 win32 侧反报 unused ignore。
