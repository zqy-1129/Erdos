> 类型：交付快照（落盘后不改写）
> 关联：SP1-3（门禁评审器：硬检查 + rubric 模型评分）、SP1-7（"门禁通过为硬条件"、失败分层归因）、DEC-005/024、《门禁硬检查接入与复核缺陷修复_2026-10-08》§4 遗留 1/5

## 1. 本轮做了什么

补齐 SP1-3 缺失的另一半，并让它进入 SP1-7 的判定通道。此前状态经逐个读代码确认：`Evaluator` 全仓只有 Protocol 无生产实现；`scripts/run_regression.py` 构造 `AcceptanceRunner` 从不传 `gate_policy`，判定通道恒走 `AutoPassGatePolicy`——即"门禁通过为硬条件"实际只有硬检查那一半在机器执行。

- **评委生产实现**（`engine/gates/llm_evaluator.py`，新增）：维度/权重/阈值/描述单源取自 rubric YAML（不在代码里硬编码评分规则，SP1-3 禁止项）；题面与产物分别按 4000/8000 字符上限投喂，截断时在 prompt 内显式声明"已截断"；模型调用失败一律上抛（伪装成"评分不通过"会把 infra 故障归因成质量问题）；`usage_sink` 如实上报评委自身 token 消耗。评分解析、重试 ≤3、转人工仍在 `GateRunner`，评委层不复制口径。
- **评分口径收口为 fail-closed**（`gates/evaluator.py::_parse_score`）：评分越出 0~1 量纲、维度漏评/多评/重名/改名一律判不通过。数值字符串仍宽容（厂商常把数字写成串）。
- **判定通道接上评委**：`RpcTaskFlow.run_stage` 从引擎检查点库回读阶段真实 `data`（原只回 `usage`，评委无从评分）；`TaskFlow` 增 `hard_reject_reason()`；`run_regression.py` 增 `--gate autopass|rubric`，rubric 口径要求真实 Key 通道否则拒启。
- **逐阶段 rubric 分数进证据面**：`ProblemResult.gate_scores`（加权分/阈值/是否通过/评委调用次数）落逐题 JSON，`report.md` 增"门禁评分"列与"rubric 评审明细"表，`summary.json` 记 `gate_mode`/`driver`/`sandbox`/`judge_usage`。
- **留痕耗时不伪造**（10-08 遗留第 5 项）：`record_model_call(duration_ms=None)` 即不落该字段；pipeline 端口未上报时记 `None` 而非 `0.0`；`__main__._build_sink` 不再 `float(..., 0.0)` 兜底。
- **不动的部分（明确边界）**：`orchestrator/graph.py` 的门禁节点仍是"硬检查自动驳回 + 人工 pass/reject"，rubric 自动评审**没有**接进生产 RPC 链路——这条 10-08 已判为 ARCH/DEC 面（自动评审与人工审批的优先级、超限是否自动驳回），且 DEC 唯一登记处《Erdos_决策记录》在工作区已丢失，无口径不实现。

## 2. 查出的缺陷（4 处，均已修）

| # | 缺陷 | 证据 | 修法 |
|-|-|-|-|
| 1 | **`_parse_score` fail-open**：评委按 0~10 分制输出时加权总分为 9.0，`>= 0.7` 直接判过；布尔 `true` 被 `float(True)=1.0` 成全分；重复维度静默丢一维 | 实现前 3 条用例红（`test_ten_point_scale_marks_fail_instead_of_auto_pass`/`test_boolean_score_marks_fail`/`test_duplicate_dimension_marks_fail`） | 量纲与维度覆盖校验，不合法判不通过 |
| 2 | **RPC 驱动遇到 `paused` 会空转到阶段超时**：硬检查驳回把 task 置 `paused`，而 `_await_stage` 只认 `done/failed` → 等满 900s 后抛 `TimeoutError`，被 `_classify_exception` 错记成**沙箱故障** | 新增 `test_hard_check_pause_fails_fast_instead_of_until_timeout`（空产出触发），修前该用例会挂到超时 | `paused` 当轮返回 + 原因经 `gate.failed` 事件捕获 |
| 3 | **硬检查驳回归因失真**：驳回后运行器继续补 `pass`，撞上"无挂起门禁"抛 `ValueError` → 归因 `orchestrator`；而 SP1-7 要求分层归因到编排/门禁/沙箱/适配器 | `test_hard_check_reject_attributes_to_gate_not_orchestrator` 修前失败在归因与错误文本 | `hard_reject_reason()` 优先判定，归因 `gate` 并带原原因 |
| 4 | **评委看不到题面无法评「问题理解」**：`Evaluator` 端口只给阶段产物；且我第一版 `--gate rubric` 的用量登记读错一层（sink 传的是 `{stage, model, usage}` 记录，代码按裸 usage 读 → `prompt_tokens` 恒 0） | `test_run_regression_gate_policy_builds_real_judge` 断言 `prompt_tokens == 11` 失败暴露 | `RubricGatePolicy` 投喂前并入题面/标题；sink 读取改 `reply["usage"]` |

缺陷 2 是"上一轮把硬检查接进编排链"引入的跨面回归——硬检查在真实 RPC 链路上驳回过几次，回归器就白等几次超时。这类"接了一条线反而更瞎"的坑只有把两侧一起跑才暴露，单侧测试全绿。

## 5. 遗留

1. **评委 prompt 未经真人 QA 校对**：投喂字段白名单（`_REVIEW_FIELDS`）按当前管线字段名写死，若 solving 产物结构再变（如新增小问分组），白名单漏项会退化为"非噪声字段全量投喂"——有兜底但可能投喂过量。
2. **评委成本未计入任务预算**：`--gate rubric` 的消耗记在回归证据面（`judge_usage`），但生产路径若将来接自动评审，评委 token 必须进 Budget（引擎方案 §7.4），否则与"token 上限"口径不符。
3. `RubricGatePolicy` 每次 `decide` 新建 `GateRunner`：重试计数按阶段独立（符合 SP1-3 口径），但跨阶段累计重试无上限——真实 Key 全量回归时单题最坏 4×3=12 次评委调用，成本上限量级需在实际跑时观察。
4. 上一批遗留未变：`gate.failed.reason` 长度未进契约、客户端 GatePanel 对 `paused` 的展示适配、`ERDOS_SANDBOX_PYTHON` 壳侧接线（W17 前置）、依赖边界守护的动态导入漏报面。
