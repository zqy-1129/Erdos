## 一、性能验收口径（执行计划）

- 生产基线：PostgreSQL，写密集场景 P95 < 200ms。
- 数据一致性：积分对账 98% 目标（当前全模块测试 + 压测场景数据一致性 100%）。
- 结论以 PG 压测为准；dev SQLite 口径仅作功能验证。

**2026-10-03 口径修订（判定集/参考集拆分）**——依据首轮 CI PG 实测暴露的三种非「生产写密集」瓶颈：
1. **同账户单行漏斗**：积分 reserve 100 并发同 user_id 为单行串行化上界，不代表生产（写分散多用户）→ 一致性断言保留，延迟入参考集；判定集改用「多用户 100 并发」场景。
2. **bcrypt CPU 红线**：注册 bcrypt cost=12 单请求 ~300ms 为 PRD 安全硬要求（非性能账）→ 入参考集。
3. **心跳分钟桶单行**：presence_minute_agg 每分钟全局单行聚合，500 并发同分钟必然串行 → 入参考集；登记优化项（分钟桶按 device/user 分片或批量聚合，见第四节遗留）。

- **判定集（Go/No-Go 门槛）**：多用户 reserve 100 并发、回调幂等重放 100、下单幂等 100 并发，P95 全部 < 200ms 即 Go（ERDOS_PERF_P95_MS 可覆盖阈值）。
- **参考集（一致性与吞吐）**：同账户 reserve 漏斗、注册防刷 50、心跳 500——断言不变（防超扣/幂等/成功率），延迟仅记录。

## 二、PG 压测操作手册（环境就绪后照此执行）

1. **拉起 PG**（任选其一）：
   - Docker：`docker run -d --name erdos-pg -e POSTGRES_PASSWORD=erdos -p 5432:5432 postgres:16`
   - 自建实例：创建库 `erdos`。
   - **CI 免环境**：直接触发 server-ci（`perf-pg` 任务内置 postgres:16 服务），或本地照 2~5 步执行。
2. **切连接串**：`ERDOS_DATABASE_URL=postgresql+asyncpg://postgres:erdos@127.0.0.1:5432/erdos`（代码双驱动，业务零改动；连接池 pool_size=10 + max_overflow=90 已于 10-03 显式配置）。
3. **迁移**：`cd server && <venv>/Scripts/python.exe -m alembic upgrade head`（先 `alembic stamp` 修正漂移，规则见 10-02 工作记录）。
4. **灌入种子**：注册 ≥ 100 用户 + 各 2 笔积分流水的演示数据（可参考 dev 库演示闭环：products + 下单→回调）。
5. **压测**：`<venv>/Scripts/python.exe scripts/stress_test.py`（6 场景：1a 同账户一致性漏斗 / 1b 多用户写密集 / 2 回调重放 100 / 3 下单并发 100 / 4 注册防刷 50 / 5 心跳 500；输出判定集与参考集 P95）。
6. **采集口径**：以压测输出「判定集」P95 为准（参考集仅记录），同时看板 /admin/ 监测区（p95_ms 红线 500ms dev 口径，PG 验收按 200ms）实时观测；导出结果追加至本报告。
7. **判定**：判定集全部 P95 < 200ms 且数据一致性 100% → 性能验收通过；否则回查慢查询（EXPLAIN ANALYZE）+ 索引（见《数据模型设计》索引与约束汇总）。
