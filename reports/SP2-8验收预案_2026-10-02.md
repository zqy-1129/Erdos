## 一、性能验收口径（执行计划）

- 生产基线：PostgreSQL，写密集场景 P95 < 200ms。
- 数据一致性：积分对账 98% 目标（当前全模块测试 + 5 场景压测数据一致性 100%）。
- 结论以 PG 压测为准；dev SQLite 口径仅作功能验证。

## 二、PG 压测操作手册（环境就绪后照此执行）

1. **拉起 PG**（任选其一）：
   - Docker：`docker run -d --name erdos-pg -e POSTGRES_PASSWORD=erdos -p 5432:5432 postgres:16`
   - 自建实例：创建库 `erdos`。
2. **切连接串**：`ERDOS_DATABASE_URL=postgresql+asyncpg://postgres:erdos@127.0.0.1:5432/erdos`（代码双驱动，业务零改动）。
3. **迁移**：`cd server && <venv>/Scripts/python.exe -m alembic upgrade head`（先 `alembic stamp` 修正漂移，规则见 10-02 工作记录）。
4. **灌入种子**：注册 ≥ 100 用户 + 各 2 笔积分流水的演示数据（可参考 dev 库演示闭环：products + 下单→回调）。
5. **压测**：`<venv>/Scripts/python.exe scripts/stress_test.py`（5 场景：reserve 100 并发、回调重放 100、下单并发 100、注册防刷 50、心跳 500）。
6. **采集口径**：以压测输出 P95 为准，同时看板 /admin/ 监测区（p95_ms 红线 500ms dev 口径，PG 验收按 200ms）实时观测；导出结果追加至本报告。
7. **判定**：全部场景 P95 < 200ms 且数据一致性 100% → 性能验收通过；否则回查慢查询（EXPLAIN ANALYZE）+ 索引（见《数据模型设计》索引与约束汇总）。
