## 2. 关键设计决策

1. **运行模式三态**（`resolveAuthRuntime`，index.ts 依环境解析）：
   - `ERDOS_API_BASE_URL` 已配置 → **cloud**（本机联调 `http://127.0.0.1:8000`）；
   - 未配置且开发期（`--dev` / `ERDOS_DEV=1`）→ **demo** 演示回退（登录页 demo-* 联调提示语义保持）；
   - 未配置且非开发期 → **unconfigured fail-closed**（登录直接报错，绝不冒充登录成功）。
2. **契约严格对齐**：注册上送 `email|phone + password + fingerprint + platform`（`additionalProperties=false`，**不送 device_id 等契约外字段**；账号含 @ → email，否则 → phone，与服务端 `find_by_identifier` 同口径）；登录仅送 `username + password`（不送 `device_id`，避免 register 签发令牌 device_id=None 与刷新设备校验冲突——服务端 `refresh` 对已设 device_id 会做一致性校验）。
3. **令牌不落盘、不出主进程**：会话由 `SessionTokenProvider` 持有（内存），渲染层仅拿到会话视图；落盘（安全存储）随后续批次接入（auth-client.ts 既有注释约定）。
4. **错误分类归因**（`classifyAuthError`，风格对齐 KeyTestOutcome）：`401→凭证错误 / 403→账号冻结 / 5xx→服务不可用 / 0→网络不可达 / 40001→参数 / 40901→已注册 / 42301→防爆破锁定`，文案为可读中文；**已知传输语义**：CloudHttpClient 对 401/403/5xx 提前抛 code=null，故这几类按 HTTP 状态归因（业务码分支仅对透传信封的响应可达，已按此收敛代码，无死分支）。

## 6. 观察项与遗留

1. **构建顺序踩坑**（已复现并归档）：`vite build` 的 `emptyOutDir=true` 会清空 `dist/`（含 `dist/main`），故 `npm run test:demo-leak` 之后必须重跑 `npm run build` 才能执行 `test:smoke`，否则冒烟报「未构建」。
2. **令牌落盘**（重启需重新登录）留待 SP3-4 安全存储接入；当前实现已预留 `TokenStore` 注入点。
3. **其余业务通道**（权益/账单/内容库/历史）仍为演示数据，待后续批次逐步接入（云鉴权通道已就绪，业务通道装配 `CloudHttpClient` 时复用 `getToken` 并挂 `onUnauthorized` 清会话）。
4. 联调账号锁定属服务端防爆破预期行为（本次演示账号 `42301` 为真实命中，锁定窗口自动解除）；演示时建议用「注册并登录」新建账号。
