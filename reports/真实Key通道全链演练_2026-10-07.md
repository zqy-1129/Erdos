## 1. 背景与价值

此前适配器 HTTP 路径仅有 httpx.MockTransport 级单元测试，**从未经「引擎进程 + stdin 首行
注入 + 真实 HTTP socket + 适配器」全链验证**——这是 11-05 真实 Key 回归前最后一个未测接缝。
本次以本地 OpenAI 兼容 mock 端点（ThreadingHTTPServer 替身）做进程级演练，把「11-05 当天
才能发现传输/注入/认证问题」的风险提前清零。

## 2. 系统测试（test_rpc_flow.py）

### 2.1 test_real_key_channel_full_chain_with_mock_vendor

真实 Key 模式（api_key + ERDOS_MODEL_BASE_URL/NAME 环境 + stdin 首行注入）四阶段全通：

- **Key 注入链路**：引擎进程 Authorization 头恰为注入 Key（`Bearer sk-test-vendor-key`），
  且仅出现于厂商请求（不出现在事件/留痕面，密钥域红线）；
- **usage 留痕**：来自厂商应答（4 阶段 × mock 用量，非估算值），runner 汇总正确；
- **产物**：论文落盘引擎 home（mock 内容含【摘要】/【结论】标记 → 管线章节抽取生效）；
- **决策门**：`real_key` 通道 1/1 通过 + 题型防偏科满足 → **GO**（判定语义在真实通道成立）。

### 2.2 test_real_key_channel_429_retry_after_through_process

EC-N2 进程级验证：mock 厂商对首次请求返回 429 + `Retry-After: 0` → 引擎内适配器重试
→ 全程成功；请求计数恰为「4 次成功 + 1 次被 429」，失败调用不计 usage。重试策略
（a17c2cd）自此在真实 HTTP 路径上闭环。

## 3. 顺带清理

  断言后未收尾 `start_stage` 创建的后台阶段任务，事件循环关闭时协程被 GC 产生
  unraisable 警告；补 `runtime.drain()`（与生产 KeyboardInterrupt 收尾路径同语义）。

  由 orchestrator/pipeline 取代。
