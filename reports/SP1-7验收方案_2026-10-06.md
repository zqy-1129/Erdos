# Erdos SP1-7 MVP 集成验收方案

> 编写日期：2026-10-06 · 状态：正式验收方案（补齐重规划 §8-8 缺口）· 判定门：2026-11-14（次日 11-15 锁引擎 MVP）
> 格式沿用 reports/SP3-7Alpha验收方案_2026-10-03.md：目的→矩阵→步骤→通过条件→证据归档。

## 1. 目的

对引擎四阶段 Agent（analysis/modeling/solving/writing）做真题端到端验收，产出"端到端成功率 ≥85%"的正式判定与失败归因报告，作为引擎 MVP（11-15）的 Go/No-Go 决策门输入。

## 2. 验收矩阵

| 维度 | 口径 | 说明 |
|---|---|---|
| 回归集规模 | ≥20 道真题，分层抽样 | 覆盖优化/评价/预测/机理 4 类题型；以《客户端与引擎开发计划》§3.2 为准（10 道为 10-01 早期口径，已废弃） |
| 模型通道 | 真实 Key 通道与 FakeLLM 通道**分开统计**（DEC-024） | FakeLLM 结果仅作回归护栏，不计入 ≥85% 判定分母 |
| 判定指标 | 端到端成功产出论文草稿比率 ≥85%；各阶段失败分布归因到模块（编排/门禁/沙箱/适配器） | 失败样本不删除，全部归因（FailureModule 分类） |
| 环境矩阵 | 开发机 Win11 + 干净 Win10 虚机各一轮 | 沙箱 subprocess 与 Docker 双模式各跑 ≥5 题 |
| 断点恢复 | 每类题型抽 1 题，阶段中 kill 后恢复续跑 | 恢复后不重放已成功副作用（DEC-005） |

## 3. 步骤

1. **真题集冻结（11-05 前）**：QA+EN 共建 ≥20 题回归集（题面/参考答案/评分 rubric 入库），冻结后不再改样本。
2. **FakeLLM 全量回归**：`scripts/run_paper_e2e.py` 一键驱动跑通全集，产出基线报告（不计入判定）。
3. **真实 Key 全量回归（11-05~11-14）**：逐题四阶段真实执行，记录 usage/耗时/失败归因；失败自动重试 ≤3 次后转人工留档。
4. **断点恢复专项**：按矩阵 kill/恢复，验证 checkpoints 幂等。
5. **判定会（11-14）**：QA 主持，EN/ARCH 参会，对照通过条件出 Go/No-Go；No-Go 走执行计划 §7-R1 预案（收缩 MVP 范围）。

## 4. 通过条件（Go）

- 真实 Key 通道端到端成功率 ≥85%（分母 = 全部真题，含失败样本）；
- 四类题型每类至少 1 题成功（防单题型偏科）；
- 沙箱双模式无 P0（Key 泄漏/数据丢失/越权路径 = 自动 No-Go）；
- 断点恢复用例全部通过；
- 失败归因报告覆盖 100% 失败样本。

## 5. 证据归档

- 判定报告：`reports/SP1-7验收报告_2026-11-14.md`（当日落盘）；
- 原始输出：`docs/acceptance/sp1-7/`（逐题 usage、事件流、产物哈希）；
- 回归集本体：内容库 problems 域 + rubric，冻结清单入判定报告附录。
