## 3. 缺口：通过率没有"怎么来的"这一栏（G41 的第三个面）

G41 原登记的是事件面（`stage.progress` 无 `tool_mode`，客户端看不见降级）。三态拆开：

| 面 | 状态 | 说明 |
|---|---|---|
| 事件面 `stage.progress.tool_mode` | ◻ 待追认 | 跨端语义（客户端要按它决定是否显示"降级"提示），需 CT 口径；本批不动 |
| 留痕侧（工具产物登记 + `tool_call` 恰一条） | ✅ 已落地 | 对齐报告 §8.6 / §8.12 |
| **验收证据面** | ✅ 本批落地 | 逐题 JSON + `report.md` 现在都带归因三件 |

落地形态：

- `ProblemResult` 新增 `solve_path` / `isolation_mode` / `dispatch_count`（`engine/regression/runner.py`）。证据 JSON 走 `asdict()`、双轨比对走 `_normalize_result()`（只剥耗时），两处都**不挑字段**，所以新字段自动参与判定，不需要在各处补登记——这正是本项目"两处各写一遍必漂移"的解法。
- `report.md` §1 增加分布行（`求解路径 stage_level 20 · 沙箱隔离 subprocess 20`），§4 逐题表增加一格 `stage_level·隔离:subprocess`。
- 语义纪律：**缺证据就写"未知"，不补一个看起来合理的值**。`solve_path=None` 表示未到 solving 阶段或产出未自述（老检查点）；`dispatch_count` 在 `stage_level` 路径是 None（该路径没有派发概念），而 `tool_loop` 派发 0 次是事实、照记 0。把"没有字段"读成"走了降级"就是编造归因——用例 `test_runner_records_none_rather_than_guessing_the_path` 专门钉这条。
- 两条路径现在都**自述** `mode`（`stage_level` 此前无该键）。这是把"靠缺字段反推路径"这个形状从代码里消掉：旧用例 `assert "mode" not in data` 表达的意图（没走循环）改用正向信号测——执行体被调用几次。

守护：`engine/tests/test_regression_path_attribution.py`（11 例，含"路径列不得凭空造值"的参数化正/反对照）+ `test_solve_loop.py` 两条改造用例。

## 4. 过程记录：自己的用例抓出自己的缺陷

`test_pipeline_stage_level_fallback_unchanged` 在我改完第一轮后变红。它原本断言"`mode` 键不存在＝没走循环"，我改成"`execute_count == 0`＝Registry 没被执行"，于是暴露出：**降级路径现在经 Registry 分发（W23②），执行的是 Registry 里的沙箱，而 `isolation_mode` 我当时读的是 `self._sandbox`**。

- 生产装配下 `__main__.py:305-308` 把同一个沙箱对象既给 pipeline 又给 registry，所以产品不会出错；
- 但"因为装配巧合所以字段为真"正是本项目反复拒绝的形状（DEC-006 要求如实上报隔离模式，G32/G41 家族都是"两处各写一遍"）；
- 修法：由**执行体自报**——`code_tools` 把 `isolation_mode` 写进 `ToolResult.data`（它手里就是真正跑代码的 sandbox），工具循环经 `SolveState.isolation_mode` 带出（`LOOP_CHANNELS` 从 `SolveState.__annotations__` 导出，加一个字段即成，两套后端共用同一声明）；pipeline 两条分支都只读带出来的值，读不到就记 `unknown`。
- 现在的断言同时测两件事：`data["isolation_mode"] == "counter"`（取自 Registry 里那个替身沙箱，而不是管线手里的 `SubprocessSandbox`）+ `inner.execute_count == 1`。

**另一条自纠**：跑测试计数时我给命令又加了一次 `-q`，而 `pyproject.toml` 的 addopts 已带 `-q` → `-qq` 把末尾"N passed"整行吞掉，看起来像输出被截。改用一键门的汇总行取数（该坑已在本机环境记忆里，本轮又踩，说明"命令带不带 -q"要当默认习惯改掉）。
