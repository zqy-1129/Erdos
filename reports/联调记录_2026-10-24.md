### 5.2 B 档：今天可跑，只差两步装配（无外部输入）

三进程同时拉起目前没有统一入口，需手工串：
1. **起服务端**：`cd server && .venv/Scripts/python.exe -m alembic upgrade head && .venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000`（**SQLite 即可，不需要 PostgreSQL/Redis/凭据**；dev 未配签名密钥会生成临时 Ed25519，属 dev 专用 fail-open）
2. **起客户端**：`ERDOS_API_BASE_URL=http://127.0.0.1:8000` + dev 标记；引擎解释器默认取 `engine/.venv`（**实测可起**：`-m engine` 直达 W40 的 `ERDOS_ENGINE_HOME` 拒启守卫，说明导入链完整），也可用 `ERDOS_ENGINE_CMD` 指向根 `.venv`。
3. **缺口**：`products` 表**无任何种子脚本与管理端写接口** → 裸起服务端后 `GET /v1/billing/products` 为空、购买流程断链（`integration-server.py:33-44` 是靠测试自己 INSERT 绕过的）。**这是 B 档唯一真正缺的东西**，且属服务端线，不由我单方补。

### 5.3 C 档：被外部条件挡住（逐项写清缺谁）

真实 Key 判定通道（需用户自带 Key，`ERDOS_MODEL_BASE_URL/NAME` 缺则引擎 fail-closed 拒启）；内容语料（`server/data/content/*.json` 仅 1.6KB 示例题；`data-platform/content` 独立平台，其 API 18789/交付包 `out/` 未与 server 打通，`handoff/BE.md:3,40` 自述"未入库、部分路由未实现"）；打包态（无 `client/resources/engine`、无 `dist`、无 PyInstaller spec → 篡改校验与版本绑定的 packaged 分支今天走不到）；Docker 强隔离（本机与 CI runner 均无 docker，沙箱降级 subprocess 并如实上报 `isolation_mode`）；遥测上云（装配用 `noopUploader`，`createCloudTelemetry` 零生产调用方 → 埋点今天不上云）；`trace_id` 六类事件全声明但客户端无消费者（崩溃/门禁归因断链）；支付/短信/SMTP/OSS 凭据（dev 下验证码直接回显在响应里，属已知 dev 语义）。
