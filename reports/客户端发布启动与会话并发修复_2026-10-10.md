## 设计、自审与复现

启动解析器、清单检查器、会话提供者与 HTTP 传输分工独立；采用 TokenStore、FetchLike、clock、getSessionRevision 等注入接口，避免上层依赖具体存储和网络实现。会话检查为每次异步边界 O(1)，刷新去重；哈希时间 O(所列资源总字节数)，清单大小上限 5 MiB、文件项上限 20000，额外文件不被递归读取。哈希按文件读入，内存受最大所列单文件影响；真实包冷启动性能仍需 W18 实测。

自审逐项检查了跨账号重试、迟到响应、错误分类/离线降级、持久化失败、运行路径/参数、生产 dev 绕路、URL/文件边界、清单版本和脚本退出码；自审发现的取消误判已修复并加入回归。同步 `client/main/engine-protocol.md` 的 W17 交接要求。清单提供完整性检查，发布可信性仍依赖包签名与可信更新源。

在 client 目录执行：

```text
npm run typecheck
npm run lint
npm run test:coverage:integration
npm run test:integration
npm run build
node scripts/scan-demo-leak.mjs
npm audit --omit=dev
npm run verify:engine-version -- --require-resources
```

最后一项在真实 W17 资源未就位时预期失败。独立服务命令依赖 server/.venv 或 ERDOS_TEST_SERVER_PYTHON。普通 test:coverage 未指定服务时有 4 个 HTTP 场景明确跳过，不能替代本批无跳过验收。
