## 1. 结论先行

1. **引擎的"能不能跑"不是当前瓶颈，"能不能被相信"才是。** 主体代码（四阶段编排/门禁/沙箱/BYOK 适配/留痕/回归）已在位且有测试；真正的缺口集中在三类：①**对外承诺无人实现**（单阶段 15 分钟、沙箱内存强制、留痕四类齐全、真实厂商联调）；②**判据没有可信出处**（数据模型文档与三处实现不对应、QA 手册用着最旧的阈值）；③**流程门没有载体**（打包未启动 → 预发与灰度两步无从执行）。
2. **本计划的主线因此不是"再加功能"，而是"把承诺变成可判定的实现，并把判据钉死"。** 五个阶段（E-A~E-E）分别对应：清障 → 兑现硬判据 → 打包与分发载体 → 真实通道判定 → 判定门会签。
3. **10-24 J-1024 这个门的性质要在评审时讲清**：它是"三进程汇合"门，不是"真实 Key"门。当前唯一可复算的证据是 mock 端点预演；真实微信/支付宝/厂商凭据（DEC-021/022）与 Linux staging 都还是外部阻塞。把 J-1024 的判据写成含真实 Key，就会在 10-24 当天被迫二选一：要么假签认，要么门失约。建议**拆成两子项**（J-1024a 三进程汇合可判 / J-1024b 真实厂商通道随凭据到位另判），需项目负责人确认。

## 2. 模块地图与技术选型

| 模块 | 职责 | 技术选型（现状） | 选型理由 | 考虑过但不选 | 风险与止损 | 唯一权威定义点 |
|---|---|---|---|---|---|---|
| `orchestrator/kernel` | 图执行、挂起/恢复、线程态 | **自研**（Python 3.12 标准库 only，约 400 行） | 摘掉 46 包闭包与 858ms import；单链/带回边拓扑不需要并行超步与 reducer | 继续用 LangGraph（成本已实测）；LangGraph 兼容层（保留框架 API 形状，会把框架词汇永久留在自己代码里） | 回退档 `ERDOS_ORCH_IMPL=langgraph`（秒级、不发版、不需数据迁移），直到 W30 摘依赖 | `kernel/spec.py`、`kernel/runtime.py` |
| `orchestrator/graph` | 四阶段顺序、门禁两态、检查点写入 | 业务逻辑单源，后端分派在 `backend.py` | 翻默认值时上线的是被 299 条既有用例钉住的逻辑，不是重复重写 | 两套完整实现（双份漂移面） | 阶段顺序/禁跳级由 `test_langgraph_orchestrator`+`test_orchestration_kernel` 双向钉 | `graph.py:STAGES/gate_node_name` |
| `orchestrator/solve_loop` | 模型驱动工具内循环 | 自研内核 + 预算路由（repair≤3、dispatch≤8） | 副作用幂等靠 `OperationLog`，与图实现无关 | 让模型自由多轮（预算红线） | 预算耗尽转 `awaiting_input`（状态命名待 G33 裁决） | `solve_loop.py:MAX_REPAIRS/MAX_DISPATCHES` |
| `checkpoint` | 阶段粒度业务检查点 | SQLite 单文件，两态 status，写读双侧拒绝第三值 | 用户机零依赖；`ORDER BY updated_at` 即恢复顺序 | 图框架 checkpointer（它是内存通道层，不是业务恢复层，两层职责不同，混用会丢恢复依据） | fail-closed：未知状态不推进而是报错保留现场 | `checkpoint/store.py:CHECKPOINT_STATUSES/gate_passed` |
| `gates` | 门禁：硬检查 + rubric | 硬检查代码级（无 LLM）；rubric 评委生产实现已具备但**未进生产编排链** | 硬检查是"执行状态+产物结构"判定，可确定、可单测；语义评分归评委 | 自动评分先于人工（属 ARCH/DEC 面，未裁决不得实现） | 评委判定通道目前只在回归器（`run_regression --gate rubric`）；进不进 graph = 待裁决项 | `gates/hard_checks.py`、`gates/rubrics/*.yaml` |
| `sandbox` | 代码执行隔离 | Docker 优先、subprocess 降级，降级**必须如实上报** `isolation_mode` | 用户机大概率无 Docker，降级是主路径；谎称等价隔离是合规问题 | 只支持 Docker（把主路径变成不可用）；Windows Job Object 前静默放宽内存上限 | 内存强制 = G9/W22（未做）；无网/非 root 在 subprocess 模式无等价物 = 待登记 | `sandbox/*.py` + 待建 `sandbox/constants.py` |
| `adapters` | BYOK 直连厂商 | `httpx` 手写 OpenAI 兼容层 + 能力探测矩阵 | 平台不中转、不代充；工具调用协议与模型调用不可分割 | LangChain 适配器（会把厂商差异藏进框架，且带 langsmith env 风险面） | 厂商行为差异未实测（G20）；默认 provider 不在矩阵（G31） | `adapters/capabilities.py`、`adapters/openai_compat.py` |
| `ipc` | stdio JSON-RPC + NDJSON 事件 | 自研（`configure_stdio` 强制 UTF-8/LF） | Windows 码页是 P0 平台事实，Linux CI 永不暴露 | 依赖框架的流式抽象 | 单行上限未实现 = G25/W36 | `contracts/engine-rpc.schema.json`（含新增 `handshake` 块） |
| `trail` | 留痕（合规硬要求） | SQLite 只追加 + 双层脱敏词表（检查点含裸 `token`，留痕不含以免误伤 `total_tokens`） | 对齐 2026 国赛 AI 工具使用规定；写失败要让任务失败 | 允许清理/保留期可配（与"禁止删除"红线冲突 = G28） | 四类事件不齐 = G10/G11/G12/W23 | `trail/store.py:EventType`、`trail/redact.py` |
| `regression` | 验收运行器 + 双通道 | 进程内 FakeLLMFlow / 子进程 RpcTaskFlow 同端口 | 真实链路（RPC）与护栏链路（进程内）共享判据，跨面回归才测得出 | 只用进程内测试（10-09 的"遇 paused 空转到超时"就是单侧全绿、两侧才炸） | 真实通道未跑（G20/W33） | `regression/runner.py:CHANNEL_*` |

## 3. 依赖关系

### 3.1 模块依赖（单向，跨进程只走契约）

```
ipc/methods ──> orchestrator/graph ──> orchestrator/pipeline ──> orchestrator/solve_loop
                     │                        │                        │
                     ├──> checkpoint          ├──> sandbox             ├──> tools/registry ──> trail
                     ├──> gates/hard_checks   └──> adapters/*          └──> adapters/*
kernel/ <─ 仅被 backend.py 装配（graph.py/solve_loop.py 不直接依赖框架）
```
- 禁止项（机器守护）：`lang*` 出现在 `engine/` 之外（现为"仅限 engine/ 内两个后端文件"，W30 后改"全仓零出现"）；引擎 import 服务端/客户端模块；`contracts/` 之外跨端直连。
- 跨面耦合点（必须一起改）：`contracts/engine-rpc.schema.json` ↔ `engine/tests/test_contract_alignment.py` ↔ `client/tests/contract-*.test.ts`。

### 3.2 工作单依赖链（不可拆的串行段）

```
既有：W2 → W6 → (W8 → W9 → W11)      W3 → W5 → W6
本批：W31(追认) ─┬─> W30(摘依赖) <─┐
                 └─> W32(灰度) <── W29/W17(打包，需批准) ──> W18(客户端打包承接)
      W34(env 注入通道) ──独立可开工
      W35(文档对齐) / W37(阈值单源) / W38(数据模型口径) / W39(provider 对齐) ──可并行，无前置
      外部阻塞：W33 与 G20 需厂商凭据；SP2-8/预发需 Linux staging
```
关键路径：**W31 → W29/W17 → W32 → W30**。其中 W29 需新增构建依赖（PyInstaller）的批准，是唯一"批了才能走"的环节。

## 5. 分阶段执行计划

> 每阶段统一格式：**目标 → 任务拆解（挂 W/G/SP 号）→ 交付物标准 → 验收准则（含复算命令）→ 回滚点**。
> 通用完成定义（DoD，所有阶段适用）：①验收命令真跑，产出"数值 + 复算命令 + commit"三件套；②状态用三态口径（已实现+生产调用方 file:line / 已实现待验收 / 设计建议）；③契约变更必须同 PR 落双侧守护；④fake 与真实分开统计；⑤遗留显式登记，不留"看起来通过"。
